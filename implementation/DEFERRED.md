# Deferred work

These are demand-driven research directions, not prerequisites hidden inside the
active phases. Start one only with a selected target, accepted claim, explicit
trust delta, bounded budget, and measurable gate. Existing Lynx support can be
reused, but still needs qualification for Pudding's claimed domain and workflow.

| Direction | Entry condition and separate obligation |
| --- | --- |
| Broader parser/validator policies | Demonstrated reuse; independently accepted policy and useful behavior, not a universal security predicate |
| Filesystem/archive extraction composition | Model consumer reinterpretation, OS path rules, symlinks/TOCTOU, permissions, and environment; byte validation alone is insufficient |
| Unicode, normalization, Windows/URL paths | Exact versioned encoding/normalization/decoding policy and boundary behavior; do not reinterpret the initial byte contract |
| Richer bit syntax, library models, higher-order/dynamic calls | Actual target gap; bounded upstream Lynx contribution with runtime/translation tests, public proof API, and invalidation |
| Stateful/concurrent programs, ETS, processes/timers | Explicit observable behavior and race domain; follow every Lynx model, footprint, exploration-soundness, and audit requirement |
| Practical resource/DoS bounds | Cost model tied to deployment and input bounds; abstract totality is not sufficient |
| Checked translation/compiler validation | Independently checkable relation from captured implementation to model; retain existing reconstruction/compiler trust until established |
| Deployment/artifact attestation | Bind checked build to actual release/load/runtime configuration; independent checking alone does not do this |
| Solver certificates and advanced automation | Demonstrated proof-search bottleneck; checked certificates or kernel proof terms, no trusted solver answers or new silent axioms |
| Coverage-guided/concolic testing | Measured discovery need and current OTP compatibility; instrumentation feedback must actually guide search, replay stays uninstrumented |
| Fine-grained/distributed proof reuse and worker pools | Module-level invalidation and economics already validated; bounded authority and complete dependency identity first |
| Alternative proof backends | A concrete unsolved requirement justifies duplicated integration/trust cost; no speculative second backend or parallel runtime |
| Broader autonomous framework analysis | Package-held-out evidence of value; policy acceptance and repair authority remain explicit |

Do not describe deferred work as supported because an upstream project has a
related feature or an external paper reports good results. Preserve unsupported
and unknown outcomes until the selected obligation actually checks.
